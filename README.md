# Semantic Cache for LLM Apps

A Streamlit application that embeds incoming questions, compares them with previously cached questions, and reuses an answer when cosine similarity reaches a configurable threshold. Cache misses call the selected provider and persist the result in SQLite.

## Features

- Local Sentence Transformer embeddings and cosine similarity
- Exact and semantic cache matching with configurable threshold and TTL
- Persistent SQLite storage with safe schema migration
- Cache isolation by provider and model
- Offline rule-based DemoProvider with professional answers and simulated LLM latency
- Demo, OpenAI, Claude, Gemini, and Ollama provider support
- Cache Explorer with selective deletion
- Evaluation dataset containing 36 positive and negative question pairs
- Easy, Medium, and Hard evaluation categories with per-difficulty accuracy
- Multi-threshold comparison with an automatic recommended threshold
- Threshold evaluation with accuracy, precision, recall, F1, and confusion counts
- Separate cache-hit and cache-miss latency metrics
- Estimated LLM cost, avoided cost, cost without caching, and savings percentage

## Request Flow

```text
User question
    ↓
Local sentence embedding
    ↓
Exact normalized match, then cosine similarity
    ↓
Similarity >= threshold?
    ├── Yes: return cached answer and record a cache hit
    └── No: call provider, cache the result, and record a cache miss
```

## Installation

```bash
python -m venv .venv
```

Activate the environment on Windows:

```powershell
.venv\Scripts\Activate.ps1
```

On macOS or Linux:

```bash
source .venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

The first run downloads `sentence-transformers/all-MiniLM-L6-v2`. Demo mode needs no API key. Cloud providers use `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, or `GEMINI_API_KEY`, together with their optional model settings. Ollama uses optional `OLLAMA_BASE_URL` and `OLLAMA_MODEL`.

## Provider Configuration

- **Demo** runs locally without an API key.
- **OpenAI** uses `OPENAI_API_KEY` and `OPENAI_MODEL`.
- **Claude** uses `ANTHROPIC_API_KEY` and `CLAUDE_MODEL` through the official Anthropic SDK.
- **Gemini** uses `GEMINI_API_KEY` and `GEMINI_MODEL` through the official Google Gen AI SDK.
- **Ollama** uses `OLLAMA_BASE_URL` and `OLLAMA_MODEL` and requires a local Ollama server.

The cache can remain isolated by provider and model so responses generated by different backends are not mixed.

## Hosted Demo vs Local Full Mode

### Hosted Demo

- Runs with the Demo Provider only and requires no API key.
- Demonstrates cache hits, cache misses, latency reduction, evaluation, and cost-saving metrics.
- OpenAI, Claude, Gemini, and Ollama are intentionally disabled.
- No visitor API keys are collected, displayed, stored, logged, or transmitted.

For a public Streamlit deployment, set this Streamlit secret or environment variable:

```toml
APP_MODE="demo"
```

Do not add external provider API keys to the public deployment.

### Local Full Mode

Local mode supports Demo, OpenAI, Claude, Gemini, and Ollama. Clone the repository, create `.env` from `.env.example`, and add only the credentials for providers you plan to use:

```dotenv
APP_MODE=local
OPENAI_API_KEY=
ANTHROPIC_API_KEY=
GEMINI_API_KEY=
OPENAI_MODEL=
CLAUDE_MODEL=
GEMINI_MODEL=
OLLAMA_MODEL=
OLLAMA_BASE_URL=
```

API keys stay in the local environment and must never be committed to GitHub. Start the full local application with:

```bash
streamlit run app.py
```

## Demo Workflow

1. Select **Demo**. It works fully offline after the embedding model is available.
2. Clear the cache if you want a clean comparison.
3. Ask `What is semantic caching?` to create a cache miss. The provider waits about 1.2 seconds to simulate an LLM call and assigns an illustrative cost of $0.002.
4. Ask `Can you explain semantic cache?` to test a semantic cache hit.
5. Compare the status, similarity, threshold, latency, provider, model, cost, and matched cached question.
6. Open **Dashboard** to compare hit and miss latency and estimated savings.
7. Open **Evaluation**, adjust its independent threshold slider, and inspect pair-level predictions, accuracy by difficulty, and the multi-threshold comparison.
8. Compare the manually selected threshold with the automatic recommendation based on F1, precision, and threshold tie-breakers.

The DemoProvider also recognizes questions about how semantic caching works, cost reduction, embeddings, cosine similarity, cache hits, cache misses, and threshold tuning. Unknown topics receive a useful offline fallback.

## Metrics Calculations

```text
cost without caching = total estimated cost across all queries
actual LLM cost      = estimated cost across cache misses
avoided cost         = estimated cost across cache hits
savings percentage   = avoided cost / cost without caching × 100
```

Zero-query and zero-cost cases safely report zero savings.

## Threshold Evaluation

The Evaluation tab uses 36 labeled question pairs: 18 positive matches and 18 negative matches. The dataset includes Easy, Medium, and Hard examples relevant to semantic caching and LLM engineering. It embeds both questions in each pair, calculates cosine similarity, applies the manually selected evaluation threshold, and compares the prediction with the expected result.

The page reports accuracy, precision, recall, F1 score, true positives, true negatives, false positives, and false negatives for the selected threshold. It also reports accuracy separately for Easy, Medium, and Hard pairs.

The multi-threshold comparison evaluates `0.60`, `0.65`, `0.70`, `0.75`, `0.80`, `0.84`, and `0.90`. The recommended threshold is the one with the highest F1 score. Ties prefer higher precision, followed by the higher threshold.

Lower thresholds generally improve recall but can introduce unsafe false positives. Higher thresholds generally improve precision but can miss valid rephrasings. Use representative domain data before choosing a production threshold.

## Limitations

- SQLite similarity lookup scans valid rows and is intended for a portfolio-scale demo.
- Semantic similarity does not guarantee factual equivalence.
- Costs are illustrative unless a provider supplies exact billing information.
- Production deployments should add tenant isolation, encryption, observability, and a vector index.
